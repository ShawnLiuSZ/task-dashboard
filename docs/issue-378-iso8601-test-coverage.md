# #378：`iso8601_to_secs` 零测试覆盖

> 断言强度审计（mutation testing）第二轮，Rust 侧纯函数审计发现。
> 所属版本：v0.3.22（待发版）· 关联 issue [#378](https://github.com/ShawnLiuSZ/task-dashboard/issues/378)

## 背景 / 动机

断言强度审计第一轮（前端 6 个纯逻辑模块）见 [`issue-376-tasksig-field-contract-test.md`](./issue-376-tasksig-field-contract-test.md)。第二轮转向 Rust 侧，首个目标就是 `common::iso8601_to_secs`：

- 被 **3 个生产模块调用**：`sync.rs` / `on_demand.rs` / `github.rs`（转换 GitHub 返回的 issue 创建/更新时间）
- 含 **Gregorian 闰年算术**：`month_adjust`（闰年且 m > 2 加一天）+ 世纪年规则（`%4 && %100 != 0 || %400 == 0`）
- 含 **6 项输入范围校验**：长度、年份下界、月份区间、日区间、时分秒上界

审计时发现：**该函数没有任何测试**。唯一的间接覆盖是 `sync.rs` 里一处 `> 0` 断言——它无法区分「解析正确」与「解析出一个荒谬但为正的值」。

这类缺陷历史上出现过：#335（`== "closed"` 写死小写，导致远程权威判定对 GraphQL 来源完全失效）同样是「纯函数细节 + 无断言守护」的组合。

## 设计 / 方案

### 为什么需要这组测试

闰年算术的两个易错点互相耦合：

1. **世纪年规则**：2100 能被 4 整除但**不是**闰年。规则一旦退化为朴素 `%4`，2100 年的所有日期偏移一天。
2. **`month_adjust` 的 `m > 2` 条件**：闰日补一天只对 3 月及以后成立；漏掉条件会让闰年 1/2 月各多加一天。

两者都不会让返回值变成「看起来不对」的 0 或负数，只会安静地偏移 86400 —— 典型的**静默失效**。

### 期望值的来源（关键决策）

**不用 Rust 闭式公式自证期望值**，而是用 Python `datetime`（标准库权威实现）算出后逐条核对。

若照抄实现的闰年公式写期望值，测试与实现同源——**同样错则同样过**，等于零覆盖。这也正是第一轮审计自己的教训：我在写跨闰日序列时手算了 `2024-02-27` 的值（`1_708_128_000`，错），测试立即失败，实际应为 `1_708_992_000`。**期望值算错是常态，必须交叉核对**。

### 三个测试的分工

| 测试 | 覆盖 | 为什么要单独一条 |
|---|---|---|
| `iso8601_to_secs_matches_reference_values` | epoch / 时分秒进位 / 平年 2 月末 / 闰日 / 闰年 3 月 / 月末进位 / 世纪年(2100) / 空白容忍 | 锁定各字段换算与闰年规则的正确取值 |
| `iso8601_to_secs_rejects_invalid_input` | 12 条非法输入（空串、纯空白、非日期、y<1970、月 13、月 0、日 32、日 0、时 24、分 60、秒 60、长度不足） | 校验分支（`return 0`）逐条覆盖。表驱动，任一守卫被删即刻暴露 |
| `iso8601_to_secs_is_continuous_across_leap_day` | 2024-02-27 .. 03-02 逐日，相邻间隔恒为 86400 | **把两个易错点组合验证**：闰年判断错时区间内会出现某天与前一天间隔 ≠ 86400 的断裂。单点用例可能碰巧对上，序列连续性不会 |

第三个测试额外断言 `expect - prev == 86_400`，让「相邻两日间隔」本身成为契约 —— 这是捕获「整体偏移」类缺陷最有效的形式。

### 边界：当前实现**不做**逐月天数校验

实现只校验 `1..=31`，所以 `2024-02-30`（日历上不存在但字段范围合法）会算出一个**语义无意义但确定**的值。

我在测试注释里显式锁定了这个真实行为并说明它**不是**完整日历校验，避免后人看到 `1..=31` 误以为已处理月末边界。**此处锁定真实行为而非理想行为** —— 若将来要加严格校验，应作为独立变更连同测试一起改。

### 本次审计的方法论教训

1. **「零测试的高调用量纯函数」应优先审**。调用点越多，缺陷波及面越大；而 `sync.rs` / `github.rs` 的时间戳都会流进 UI 展示。
2. **每次注入都要确认注入生效**。本轮我第一版 `python3 -c` 因 `$` 被 shell 吞掉报了「注入失败」，若采信该输出就会把「注入失败」误判为「断言失效」（第一轮已踩过这个坑，见 #367）。
3. **变异设计要能区分语义**。第一轮我把「只跑一次」写成 `for (let once = true; once;)` —— 那是**无限**循环不是单次，等价变异，会浪费一轮判断。
4. **期望值必须外部来源**。手算必错，用 Python 交叉核对。
