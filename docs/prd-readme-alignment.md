# 收敛 PRD / README 口径：3 处硬约束矛盾就地对齐

> 来源：`PRODUCT-REVIEW-2026-11-11.md` 想法清单 P1 第 3 条 ——「收敛 PRD / README 口径」。
> 本文是该想法的落地实现记录。

## 背景 / 动机

[PRD.md](../PRD.md) 停在 v0.3（2026-09-03），此后实现已大幅演进（MCP 内置、Projects v2
放弃、closed 自动归入、显式写回通道）。**约束有两个版本时，下个 agent 会挑一个执行**——
所以这不是文档洁癖，是会实际改变 agent 行为的隐患。盘点 §4.3 列出 3 处硬约束矛盾：

| # | 位置 A（PRD/README 旧） | 位置 B（AGENTS/README 现行） | 裁定 |
|---|---|---|---|
| 1 | PRD §9 D1/D4/D5/D6「待确认」、D3「Projects v2 ✅」、§10「暂不做 MCP」 | AGENTS §3 / README MCP 章节：MCP 已内置、39 agent 接入；Projects v2 已放弃 | 以 AGENTS/README 为准 |
| 2 | PRD §4.2.1：closed → 候选已完成、需显式确认 | AGENTS §2.2：`gh_state == closed → done`（远程权威覆盖） | 以 AGENTS 为准 |
| 3 | README 三处「绝不写回 GitHub」 | AGENTS §2.1：用户 UI 确认框后的显式写回（#214/#215） | 以 AGENTS 为准，README 补例外 |

维护者裁定（2026-11-11）：**全按盘点建议，以 AGENTS/README 为准**重写 PRD 的硬约束。

## 设计 / 方案

**就地标注修正，不重写整篇 PRD。**

关键决策：

- **以「横幅 + 就地 ⚠️ 标注」代替整篇重写。** PRD 的价值在「决策演进记录」，整篇重写会
  抹掉历史脉络。改为：头部加一条**口径对齐声明**（凡冲突处以 AGENTS/README 为准），
  再在 3 处矛盾点就地加 ⚠️ 标注，写明「历史设计 vs 现行口径」与权威指向。这样既消除歧义，
  又保留 PRD 作为演进记录的可读性。
- **不改动 AGENTS.md / 现行 README 行为表述。** 它们是权威侧，无需改；只把过时的
  PRD 拉齐、给 README 的绝对化「绝不写回」补上例外说明。
- **README 只补例外，不改承诺。** 「纯本地零副作用」是对外承诺，保留；仅在 3 处
  「绝不写回」后补一句「用户 UI 确认框后的显式写回（#214/#215）除外，见 AGENTS §2.1」，
  使对外表述与实现一致。

## 接口 / 行为变更

无代码 / 接口 / DB 变更。纯文档（`PRD.md` + `README.md`）。

- `PRD.md` §4.2.1：加 ⚠️ 标注——closed 现行自动归入「已完成」（远程权威覆盖），
